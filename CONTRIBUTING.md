# Contributing

Thank you for your interest in improving Open Research Central Asia. Contributions from researchers, lecturers and students are all welcome.

## Ways to contribute

- **Report a problem**: open an issue describing what you ran, what you expected and what happened (include your R/Stata version).
- **Suggest a data source**: add it to `docs/data-sources.md` with a one-line description and how to access it.
- **Add a workflow**: a new research example (R and/or Stata) following the structure below.
- **Improve teaching material**: exercises, solutions, translations (Uzbek, Russian, Kazakh, Kyrgyz, Tajik).

## Coding conventions

1. **Comment generously.** Every script starts with a header block (purpose, input, output). Explain *why* a choice is made, not just *what* the code does; many readers are students.
2. **Numbered scripts.** Scripts run in order: `01_`, `02_`, ... plus a `run_all` file.
3. **Relative paths only.** Never use `C:/Users/...`; paths are relative to the project root.
4. **Raw data are read-only.** All cleaning happens in code.
5. **Do not commit data or outputs.** They are regenerated by the scripts (`.gitignore` handles this). Never commit restricted microdata.
6. **Keep R and Stata in sync.** If you change a model in one language, update the other or note the difference.
7. **R style:** tidyverse style, native pipe `|>`, snake_case names.
8. **Stata style:** `///` for line continuation, labelled variables, `version` statement in setup.

## Before opening a pull request

- Run the full workflow on simulated data: `Rscript R/run_all.R simulate`.
- If you added a package, add it to `required_packages` in `R/00_setup.R` (or to the SSC list in `stata/00_setup.do`).
- Update `README.md` if you added a workflow or changed how something is run.

## Code of conduct

Be respectful and constructive. This is an academic project built in good faith; critique ideas, not people.
